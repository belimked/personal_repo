# 个人日常助手 · 设计资料与版本管理

本仓库保存设计阶段的全部产物：原型、需求文档、设计文档和调研资料，按**迭代（ITER）+ 版本（v1、v2、v3…）**管理。

## 版本规则

1. 每个迭代一个目录，目前是 `ITER1`（迭代一）。
2. 原型、需求文档、设计文档**各自独立编号**，例如原型已到 v2 时，需求文档可以还是 v1。
3. **用户没有明确要求出新版本时，所有修改都在当前版本中进行**；只有用户明确要求时才新建下一个版本，此时上一版本冻结、不再修改。
4. 新版本从上一版复制出来再改，旧版本保持原样、可随时打开对比。当前版本的 git 标签随修改移到最新提交，冻结后不再移动。
5. 每发布一个新版本：更新下方"版本索引"、原型首页 `public/index.html`，并打 git 标签，格式为 `ITER1-proto-v2`（原型）、`ITER1-req-v1`（需求）、`ITER1-design-v1`（设计）。
6. 不同原型版本在浏览器里的演示数据分开保存，互不影响。

## 目录结构

```
README.md                       本文件：版本规则与索引

  index.html                    原型版本首页
  404.html
  ITER1/v1/                     原型 v1（冻结）
  ITER1/v2/                     原型 v2（冻结）
  ITER1/v3/                     原型 v3
docs/                           不发布，只保存在仓库中
  ITER1/research/               调研资料
  ITER1/review/                 原型评审变更记录（编写需求文档时的输入）
  ITER1/requirements/           需求文档：需求文档-v1.md、需求文档-v2.md…
  ITER1/design/                 设计文档：设计文档-v1.md…
```
