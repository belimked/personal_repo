# v0.9.8：语音请求显示判断和进度；位置与路线预估

- 日期：2026-11-12
- 用户已定：路线用 Apple 地图；“去 X 要多久”和日程“该出发了”都要，只给预估，要看详细路线就打开手机地图 App；进入 App 时申请一次定位权限（使用期间），之后不再弹窗。
- iOS 只新增一个原生依赖：`expo-location`，**固定为 `58.0.17`（不能加 ^ 或 ~）**。这是 Expo SDK 58 配套的版本，发布时间早于 expo-modules-core 58.0.22，避免 0.9.5 那种符号缺失导致的闪退。不能加别的依赖，打开地图用 React Native 自带的 `Linking`。

## A. 语音请求：显示判断结果和进度

### A1 后台
- 迁移 0008：
  - `recordings` 加 `intent TEXT`、`step TEXT`；
  - `messages` 加 `meta TEXT`（JSON）；
  - 新表 `user_locations(user_id TEXT PRIMARY KEY, lat REAL, lng REAL, accuracy REAL, at TEXT)`。
- 处理“说一句”语音（kind=voice）时，按下面顺序更新 `step`，App 轮询时能看到：
  1. 转写结束、开始判断：`step='正在判断是什么事'`。
  2. 判断分两步：
     - 用现有 jev 判断场合，结果是 work、life 或 mixed。
     - 再调一次 `XIAOHE_MODEL_ASK`（flash，超时 10 秒）判断意图。传入今天的日期（Asia/Taipei）和转写文字，要求只返回 JSON：`{"intent":"search|remind|route|other","query":"搜索要搜的话或null","title":"提醒事项标题或null","remind_at":"YYYY-MM-DDTHH:MM或null","place":"目的地或null"}`。
     - 先取花括号里的内容再解析；解析失败按 `other` 处理。
  3. 写入 `intent`：
     - 意图是 search、remind、route 时，`intent` 就是对应的值；
     - 意图是 other 时，`intent` 用场合的结果（work、life 或 mixed）。
  4. 按 `intent` 设置 `step`，然后执行：
     - **search**：`step='正在搜集资料'`。
       - 把 `ask` 的核心逻辑抽成函数 `askResult(uid, q)`，返回 answer、things、files、said。HTTP 接口 `/api/ask` 改成调用这个函数，对外行为保持不变。
       - 回复内容是：answer 加上前 5 件事（格式和 App 打字搜索一致），助手消息的 meta 写 `{"search": query}`。
       - 计入 search_uses。
       - 这条语音不提取事项。
     - **remind**：`step='正在创建提醒'`。
       - 新建一个 todo：`{title, due: remind_at 的日期, remind_at: remind_at 转成 UTC ISO, done:false, scene, source:{type:"recording", recording_id}}`。
       - 回复“好，<M月D日 HH:mm> 提醒你：<title>”。
       - 如果 remind_at 为空，就按普通请求处理。
     - **route**：`step='正在估算路线'`，按 B2 计算。
       - 回复示例：“从你现在的位置去<地点名>，开车约 N 分钟，公交约 M 分钟（预估）”；公交没有结果时不提公交。
       - 助手消息的 meta 写 `{"route":{"name","address","lat","lng"}}`。
       - 下面三种情况只回复说明，不报错：没有位置（或位置超过 12 小时）回复“打开小禾时还没拿到你的位置，开启定位后再问我”；地图没配置回复“路线预估还没开通”；找不到地点回复“没找到<地点>”。
     - **work、life、mixed**：如果场合判断要提取事项（ExtractWork 或 ExtractLife），`step='正在创建任务'`，否则 `step='正在整理资料'`。之后按现有流程处理：提取事项，并用 voiceReply 回复。
  5. 处理完成后 `step` 保留最后一步，不用清空。
- 会议录音和资料（meeting、file）：开始整理时 `step='正在整理资料'`，开始写入事项时 `step='正在创建任务'`，`intent` 用场合的结果。
- `GET /api/recordings/{id}` 和录音列表的返回里增加 `intent`、`step`。消息接口（`/api/messages`、`/api/home`）的返回里增加 `meta`，内容是 JSON 对象，没有就是 null。
- 纪要的 action item 增加可选字段 `place`：只有录音里明确说了地点才填。建事项时写进 `data.place`。`/api/messages/convert` 的提示词也加上 `place`。

### A2 App
- 按住说话后：先 toast“收到”，滚到这条语音（这部分已经有，保持不变）。
- 语音气泡 `VoiceNote` 的文字改为：`语音 0:05 · <标签> · <进度>`。
  - 标签：search→搜索，remind→提醒，route→路线，work→工作，life→生活，mixed→混合。还没有 intent 时不显示标签。
  - 进度：
    - queued 或 transcribing：“正在转成文字”；
    - summarizing：显示后台的 `step`，没有 step 时显示“正在判断是什么事”；
    - done：“已回复”；
    - failed：维持现在的显示。
- 首页按钮下方的提示 `voiceTip` 用同样的文字，例如“工作 · 正在创建任务…”。不再显示“小禾正在想怎么回你”。
- 收到的消息有 `meta.search` 时显示“看全部结果”（现在已有，改成从 meta 读）；有 `meta.route` 时显示“在地图中打开”，点了用 `Linking.openURL('maps://?daddr=<lat>,<lng>&q=<name>')` 打开系统地图。

## B. 位置与路线

### B1 App（`expo-location@58.0.17`）
- `app.json` 的 plugins 加 `["expo-location", {"locationWhenInUsePermission": "小禾用你的位置估算去日程地点要多久，只在你打开小禾时获取。", "isIosBackgroundLocationEnabled": false, "isAndroidBackgroundLocationEnabled": false}]`。
- 新建 `src/lib/location.ts`：
  - **进入 App 时申请一次权限**：登录后（store 有 token，演示模式除外）调用 `requestForegroundPermissionsAsync`。只在状态是 undetermined 时申请，之后不再申请。
  - 位置上传的条件：有权限，并且 `setting-sensitive` 的 `location` 不是 false。满足时，在 App 启动和回到前台时调用 `getCurrentPositionAsync({accuracy: Balanced})`，`PUT /api/me/location {lat,lng,accuracy}` 上传。同一台设备 10 分钟内最多上传一次。
  - `location` 开关从开变成关时，调用 `DELETE /api/me/location`。
  - 所有定位错误都不打扰用户，也不弹窗。
- 首页打字面板：消息匹配 `/^(从这里)?(去|到).{1,30}(要多久|多久|多远|怎么走)/` 时走路线预估。先取当前位置（失败就不带坐标，由后台用最后一次上传的位置），调用 `POST /api/route {to, lat?, lng?}`，回复气泡显示估算结果和“在地图中打开”。
- 日程页（`app/schedule.tsx`）和逐件过页：事项有 `data.place` 时显示地点。有 `data.eta` 时显示“开车约 N 分钟”。地点旁边有一个“导航”按钮，打开 `maps://?daddr=...`，有坐标用坐标，没有坐标就用地点名。
- “我的”页的“隐私与个人信息”页底部加一行说明：“位置只在打开小禾时获取，只保留最近一次，用来估算路线”。
- 版本 0.9.8，buildNumber 5。

### B2 后台（Apple Maps Server API）
- 环境变量：
  - `XIAOHE_APPLE_MAPS_TEAM_ID`、`XIAOHE_APPLE_MAPS_KEY_ID`：Apple 开发者账号里 Maps 专用的 key；
  - `XIAOHE_APPLE_MAPS_KEY`：.p8 私钥文件路径；
  - `XIAOHE_APPLE_MAPS_BASE`：默认 `https://maps-api.apple.com`，测试时指向假服务。
- 三个变量缺任何一个，就算“未配置”：路线功能返回 503 `maps_not_configured`，其他功能不受影响。
- 鉴权：
  - 用标准库 `crypto/ecdsa` 生成 ES256 JWT，header 是 `{alg:ES256,kid,typ:JWT}`，payload 是 `{iss:teamId,iat,exp:+30min}`。**不能新增 Go 依赖**。
  - 用这个 JWT 调 `GET /v1/token` 换 accessToken，缓存到过期前 1 分钟。
- 地点查询：`GET /v1/geocode?q=<地点>&searchLocation=<lat,lng>&lang=zh-CN`，没有结果时再试 `/v1/search?q=...&searchLocation=...`。取第一个结果的 name、formattedAddressLines、coordinate。
- 时间估算：`GET /v1/etas?origin=<lat,lng>&destinations=<lat,lng>&transportType=Automobile`，再用 `Transit` 调一次（失败就忽略），取 `expectedTravelTimeSeconds`，换算成分钟。
- 接口：
  - `PUT /api/me/location`：参数 `{lat,lng,accuracy}`，校验坐标范围后写入或覆盖 user_locations。如果 sensitive.location=false，就删除位置并返回 `{ok:true,stored:false}`。
  - `DELETE /api/me/location`。
  - `POST /api/route`：参数 `{to, lat?, lng?}`，返回 `{place:{name,address,lat,lng}, driving_min, transit_min|null, from:"device|last", maps_url}`。没带坐标时用 user_locations（12 小时内），都没有就返回 400 `no_location`。
- **出发提醒**写进现有的 remind 任务（每 5 分钟一次）：
  - 处理范围：本人未完成的 todo，`data.place` 不为空，due 带具体时间（含 `T` 和时:分）且是今天，用户 12 小时内上传过位置，地图已配置。
  - 地点坐标缓存在 `data.place_geo`。
  - 离 due 不到 3 小时、并且没有 `data.eta` 或 `data.eta.at` 已经超过 30 分钟时，重新算一次开车时间，写入 `data.eta={minutes, transit_minutes, at}`。
  - 当 `now >= due - eta.minutes - 15 分钟`，并且还没推送过（没有 `data.depart_pushed`）时：推送标题“该出发了：<title>”，正文“去<地点>开车约 N 分钟（预估）”，推送 data 是 `{type:"remind", item_id}`，然后写入 `depart_pushed`。
  - 一个用户每轮最多算 5 件，避免调用太多。
- 导出数据里包含 user_locations；“忘掉我”不删除位置。
- 测试：
  - 假 Apple 服务：token、geocode、etas；
  - route：带坐标、用最后位置、没有位置、未配置；
  - 位置的写入、删除和敏感开关；
  - 出发提醒：到点推送一次，不重复推；
  - 语音意图：search、remind、route、other 四种分支和 step 的变化（假 LLM）。
