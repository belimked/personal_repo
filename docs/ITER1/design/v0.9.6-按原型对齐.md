# v0.9.6：登录后的界面按原型（app-ios-unslop）对齐

- 日期：2026-11-12
- 状态：已定（用户 11-12 选 B：App 往原型改；小差异都要改）
- 原型：`docs/ITER1/ui/drafts/app-ios-unslop/01～06-*.png|html`（布局、文字、顺序以 PNG 为准）
- 原则：**布局、文字、顺序照原型；原型里的数字和状态要有真实来源，没有来源的不造假**（见第 3 节例外）。演示模式不动（已和原型一致）。
- 硬性：**iOS 不加任何新的原生依赖**（0.9.5 闪退教训）。分享用 React Native 自带 `Share`，文件用已固定的 `expo-file-system@58.0.10`，手势用 `PanResponder` + `Animated`。

## 1. 后台

### 1.1 每件事的“办法”（原型 01 的副标题、02 的“建议回复”框）
- 纪要提示词里每个 action item 增加两个字段：`suggest`（一句话建议怎么办，≤40 字，只依据录音内容，不编造）和 `suggest_short`（≤14 字，用在封面副标题，例如“建议周五前办，已排好”）。建事项时写进 `data.suggest`、`data.suggest_short`。
- 旧事项补齐：`/api/home` 返回前，找出本人“今天要办（todo 未办完且 due≤今天）+ 等你定（idea/stash，排除演示事项 demoItem）”中缺 `suggest` 的，最多 8 条，**异步**（goroutine，同一用户同时只跑一个）调用 `XIAOHE_MODEL_JOB` 生成，输入是事项标题、负责人、due 和来源录音的纪要摘要（有的话），写回 data。本次请求不等它，下次 home 就有。
- 失败不重试风暴：生成失败的写 `data.suggest_error_at`，24 小时内不再试。

### 1.2 交链接（原型 04“拍照、文件、链接”）
- `POST /api/files/link`，请求 `{"url":"https://..."}`。
- 只允许 http/https；DNS 解析后拒绝私网、回环、链路本地、组播、0.0.0.0/8、100.64/10、198.18/15 地址（每次跳转都重新检查，最多 3 次跳转）；连接时用解析出的 IP 拨号，防 DNS 重绑定；超时 15 秒；正文最多 5 MB；只接受 text/html、text/plain。
- 去掉 script/style/nav/footer，取 `<title>` 作标题，正文转纯文本，保存成 `.txt`，按 kind=file 建 recording（mime `text/plain`，title 用网页标题），唤醒队列，走现有资料流程。`data` 里记 `source_url`。
- 失败返回 400 `invalid_link`（中文说明：打不开 / 不是网页 / 太大）。
- 测试用 httptest 起本地服务时，私网检查要能在测试里关掉（例如 API 上加 `AllowPrivateLinks bool`，只在测试设为 true）。

### 1.3 通知级别（原型 05“通知：只发错过就晚的”）
- 用户设置 items `id='setting-notify'`，`data.value` 为 `all`（默认）/ `urgent` / `off`。
- `pushUser` 发送前检查：`off` 全不发；`urgent` 只发 `type=remind`、录音或资料**失败**、以及纪要里新增了 due≤明天的待办；`all` 和现在一样。早报、周回顾在 `urgent` 下只在有已过期事项时推送。

### 1.4 点数（原型 05“会员与点数：本月剩 320 点”）
- 内测不扣费、不拦截，只按用量计算，让数字有真实来源。
- `GET /api/points`：`{"quota":500,"used":N,"left":500-N,"month":"2026-11","detail":[{"label":"对话","count":x,"points":x},...]}`。
- 本月（Asia/Taipei）用量现算，不建账本：对话（home 线程 user 消息）1 点/条；按意思搜索 1 点/次（新表或 audit 计数均可，实现者定，要能按月统计）；语音 1 点/条；会议录音 每 10 分钟 5 点（不足按 10 分钟算）；资料 3 点/份。
- 额度 `XIAOHE_MONTHLY_POINTS`，默认 500。

### 1.5 我了解的你（原型 06）
- profile 任务新建的 fact 带 `data.auto=true, data.confirmed=false`；用户手动确认后 `confirmed=true`（App 用现有 items PATCH）。
- 敏感类别：用户设置 `id='setting-sensitive'`，`data.value` 为对象 `{"health":true,"finance":true,"kids":true,"location":true,"face":false}`（缺省即此值，“4 项开”）。profile 任务提示词里，关掉的类别明确写“不要记录 X 相关事实”，且 `health=false` 时丢弃 group=健康 的结果。
- `GET /api/export`：返回本人全部数据 JSON（user 公开字段、items、messages、recordings 元数据和纪要、briefs），`Content-Disposition: attachment`。写 audit。
- `POST /api/forget`：把本人所有 kind=fact 的事项标记删除，并删除 job_runs 里本人 profile 的记录（让以后重新学）。返回删除条数。写 audit。
