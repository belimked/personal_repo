- 日期：2026-11-10
- 状态：待确认
- 范围：把 v7 的 Cloudflare Worker 后台换成部署在 65 上的 Go 后台，并加上会议录音转写和纪要整理。Web 静态页面仍放在 Cloudflare。


## 3. Go 后台

### 3.1 技术选择

- Go 1.23 以上；只用标准库 `net/http`（1.22 起支持 `GET /api/items/{id}` 这种路由），不引入 Web 框架。
- SQLite 用 `modernc.org/sqlite`（纯 Go，不需要 cgo，交叉编译和 runner 编译都简单）。
- 密码哈希用 `golang.org/x/crypto/pbkdf2`，参数和 Worker 完全相同（PBKDF2-SHA256、10 万次、16 字节盐、32 字节结果，十六进制存储），所以 D1 里的账号可以原样迁移，用户不用改密码。
- 时间统一按 UTC 的 ISO 8601 字符串存储，和现有 D1 数据格式一致。
- 一个可执行文件 `xiaohe`，子命令：`serve`（默认）、`migrate`、`backup <路径>`、`import-d1 <sql 文件>`。

### 3.2 代码位置（放在现有公开仓库）

```

  cmd/xiaohe/main.go
  internal/api/         路由与处理函数
  internal/store/       SQLite 访问
  internal/asr/         调 63 的客户端与转写队列
  internal/llm/         调 api.belimked.com
  migrations/           0001_init.sql（同现有表）、0002_recordings.sql …（用 embed 打进程序）

.github/workflows/deploy-api.yml
```

### 3.4 接口

**沿用 v7 的全部接口，路径、参数、返回格式、错误码都不变**（见 `v7-api.md`），包括：健康检查、登录 / 退出 / `me`、`items` 增删改查、`chat`、`messages`、管理端账号 / 测模型 / 设置 / 操作记录。行为细节照搬 Worker：

- 鉴权 `Authorization: Bearer <token>`，token 30 天有效；
- 管理员看不到用户的 items、messages，**也看不到录音和转写内容**；
- 对话限流每分钟 10 次、每天 200 次；上游失败返回兜底回复；
- 管理端设置拒绝保存密钥类配置；
- 演示账号：表为空时自动写入（迁移后表不为空，不会重复写）。

`/api/health` 改为返回更多信息，旧字段保留：

```json
{"ok": true, "version": "go-<commit>", "db": "ok", "asr": "ok|down", "queue": 0}
```

**新增：录音与会议纪要**

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/recordings` | `multipart/form-data`：`file`（m4a / opus / mp3 / wav），`title?`，`recorded_at?` → `{recording}`，状态 `queued` |
| GET | `/api/recordings?since=<ISO>` | 当前用户的录音列表，含状态 |
| GET | `/api/recordings/{id}` | 单条状态：`queued` / `transcribing` / `summarizing` / `done` / `failed`，以及 `queue_position`、`error` |
| GET | `/api/recordings/{id}/transcript` | `{text, segments:[{start_ms,end_ms,speaker,text}], speakers}` |
| GET | `/api/recordings/{id}/minutes` | `{title, summary, decisions[], action_items:[{text, owner?, due?}]}` |
| POST | `/api/recordings/{id}/retry` | 失败后手动重试 |
| DELETE | `/api/recordings/{id}` | 删除录音、转写和纪要（音频文件立即删除） |
| GET | `/api/admin/asr` | 管理端：63 是否在线、排队数量、最近 20 条任务的耗时和结果（**不含内容**） |

**新增：推送设备**

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/devices` | `{token, platform:'ios', env:'production'\|'sandbox'}`，App 登录后和每次启动时上报；同一 token 换了账号就改归属 |
| DELETE | `/api/devices/{token}` | 退出登录时调用 |

上传限制：

- 单个文件不超过 **95 MB**。Cloudflare 免费套餐的请求体上限是 100 MB；1 小时会议压成 m4a 约 30 MB，足够。
- App 上传前先压成 m4a（AAC 单声道 32–64 kbps）；Web 端允许直接传 wav，超限时提示。
- 每个用户每天最多上传 20 条、合计 5 小时。
- 上传接口只负责收文件并排队，马上返回。Cloudflare Tunnel 单个请求约 100 秒超时，所以转写不能放在请求里同步等待。

### 3.5 数据表

`0001_init.sql` 原样保留（`users`、`sessions`、`items`、`messages`、`audit`、`settings`），另加：

```sql
-- 0002_recordings.sql
CREATE TABLE recordings (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL,
  title TEXT,
  mime TEXT NOT NULL,
  size_bytes INTEGER NOT NULL,
  duration_s REAL,                 -- 由 63 返回后回填
  audio_path TEXT,                 -- 删除音频后置空
  status TEXT NOT NULL CHECK(status IN ('queued','transcribing','summarizing','done','failed')),
  attempts INTEGER NOT NULL DEFAULT 0,
  next_try_at TEXT,                -- 63 不在线时的下次重试时间
  error TEXT,
  recorded_at TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  finished_at TEXT,
  audio_deleted_at TEXT
);
CREATE INDEX recordings_owner ON recordings(user_id, created_at);
CREATE INDEX recordings_queue ON recordings(status, next_try_at);

CREATE TABLE transcripts (
  recording_id TEXT PRIMARY KEY,
  text TEXT NOT NULL,
  segments TEXT NOT NULL,          -- JSON
  speakers INTEGER,
  minutes TEXT,                    -- JSON，纪要
  asr_model TEXT,
  asr_elapsed_s REAL,
  created_at TEXT NOT NULL
);

CREATE TABLE devices (
  token TEXT PRIMARY KEY,          -- APNs device token（十六进制）
  user_id TEXT NOT NULL,
  platform TEXT NOT NULL,
  env TEXT NOT NULL,
  created_at TEXT NOT NULL,
  last_seen_at TEXT NOT NULL
);
CREATE INDEX devices_owner ON devices(user_id);

CREATE TABLE schema_migrations (version TEXT PRIMARY KEY, applied_at TEXT NOT NULL);
```

SQLite 打开时设置：`journal_mode=WAL`、`busy_timeout=5000`、`foreign_keys=ON`、`synchronous=NORMAL`。

**迁移规则：只增不改。**新迁移只能加表、加列、加索引，不删列、不改列含义。这样发布失败把程序回滚到旧版本时，旧程序仍然能用新表结构。

### 3.6 转写和纪要流程

```
上传 → queued
      │ 后台队列（单线程，每 5 秒查一次，按 created_at 先进先出）
      ▼
transcribing ── POST 63 /transcribe ──► 返回文字 + 时间戳 + 说话人
      │ 成功：写 transcripts，回填 duration_s
      ▼
summarizing ── 调 deepseek-v4-pro 整理纪要（JSON 输出）
      │ 成功：写 transcripts.minutes；行动项自动建成事项；往 home 对话发一条助手消息；推送
      ▼
done
```

- **同一时间只转一条**。63 是单机 CPU 转写，并发只会互相拖慢。
- 调 63 的超时 = `max(10 分钟, 音频时长 × 0.6)`。实测比例约 0.2，留足余量。
- **63 不在线**（连接失败、超时、`/health` 不通）：任务回到 `queued`，`next_try_at` 按 1、2、5、10、30 分钟递增，之后每 30 分钟试一次；这种情况**不计入失败次数**，63 开机后自动接着做。
- **63 返回错误**（文件损坏、格式不支持等）：`attempts + 1`，满 3 次标为 `failed`，`error` 写给用户看的中文说明。
- **纪要整理失败**：同样最多 3 次；转写结果已保存，失败时用户仍能看到原文。
- **后台重启**：启动时把所有 `transcribing`、`summarizing` 改回上一步重新做。
- **通知 App**：纪要做好后两件事一起做：
  1. 在 home 对话里发一条助手消息（符合 v4 定的“助手整理好再发消息”）；
  2. 通过 APNs 推送到该用户的所有设备，见 3.7。
  App 打开录音详情时每 10 秒查一次状态，作为推送收不到时的兜底。转写失败（`failed`）也推送一条。
- **纪要提示词**：输入带说话人标签的逐句文本（“说话人 1：…”）和用户显示名，要求输出 JSON：标题、三到五句摘要、已定事项、行动项（内容、负责人、期限、负责人是否是用户本人；没提到就留空）。1 小时会议约 1.5 万字，模型上下文放得下；超过 4 万字时先分段摘要再合并。
- **行动项自动建成事项**（走和 `POST /api/items` 相同的写入逻辑，App 同步时就能看到）：

  | 行动项 | 建成 | 说明 |
  |---|---|---|
  | 用户本人或没写负责人，有期限 | `todo` | 日期取期限 |
  | 用户本人或没写负责人，没期限 | `idea`（想做的事） | 按 v5 规则：待办必须有日期 |
  | 别人负责 | `watch`（我盯着的事） | 记下负责人和期限 |

  - 每个事项 `data` 带 `source: {type:'recording', recording_id, index}`，App 里能点回原纪要和对应原话。
  - 事项 id 由 `recording_id + 序号` 生成，重试纪要整理时只会覆盖，不会重复建。
  - 助手消息里列出建了哪些事项，用户觉得不对可以直接删，删除走现有软删除。
  - 用户删除录音时，自动建的事项**保留**（已经是用户的事项了）。

### 3.7 推送（APNs）

- **直接调 Apple**，不经 Expo 推送服务或其他第三方，推送内容不出我们和 Apple 之外。
- App 端用 `expo-notifications` 申请权限，取**原生 APNs device token**（`getDevicePushTokenAsync`），上报 `POST /api/devices`。
- 后台用 token 方式鉴权：`.p8` 密钥签 ES256 JWT（每 50 分钟换一次），HTTP/2 调 `api.push.apple.com`。用 Go 标准库实现，不引第三方推送库。
- 推送内容只写结果，不写会议内容：
  - 成功：标题“会议纪要整理好了”，正文“<纪要标题> · 新增 N 件事”；
  - 失败：标题“录音没能转写”，正文“点开看原因，可以重试”。
  - 自定义字段 `{recording_id}`，点通知直接打开这条录音的纪要。
- Apple 返回 `410 Unregistered` 或 `400 BadDeviceToken` 时删掉这个设备；其他错误重试 3 次后放弃（对话里的消息仍在，不会漏）。
- 管理端设置 `push_enabled`，出问题时可一键关掉。
- **前置条件（Apple 侧，见第 12 节）**：现在的 Ad Hoc 描述文件里**没有推送权限**（`aps-environment` 缺失），要先在开发者后台给 App ID 打开 Push Notifications、建 APNs 密钥，再重新生成描述文件，更新 GitHub Secrets `IOS_ADHOC_PROFILE_BASE64`。`app.json` 加 `expo-notifications` 插件。

### 3.8 音频保留

- 转写完成后，原始音频默认保留 **7 天**再删；`failed` 的保留 30 天方便重试。天数是管理端设置 `audio_retention_days`。
- 每小时清理一次，删除文件后置空 `audio_path`，写 `audio_deleted_at`。
- 转写文字和纪要一直保留，直到用户删除这条录音或删除账号。
- 63 处理完每个请求就删自己的临时文件，不留副本。

## 4. 63 转写服务

### 4.1 程序

- 位置：`F:\asr\service\server.py`，用已有的 FunASR 虚拟环境（funasr 1.4.24、torch 2.5.1 CPU），加装 `fastapi`、`uvicorn`、`python-multipart`。
- 启动时加载一次模型，之后常驻内存：`paraformer-zh` + `fsmn-vad` + `ct-punc` + `cam++`（说话人），`device=cpu`。和测试脚本 `run-f.py` 的配置一致。
- 收到的音频先用已有的 `F:\ffmpeg-master-latest-win64-gpl-shared\bin\ffmpeg.exe` 转成 16 kHz 单声道 wav，再交给模型。
- 监听 `0.0.0.0:11226`。

### 4.2 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | `{ok, model, busy, version}`，不需密钥 |
| POST | `/transcribe` | 请求头 `X-ASR-Token`；`multipart` 字段 `file`、可选 `hotwords` → `{duration_s, elapsed_s, text, speakers, segments:[{start_ms,end_ms,speaker,text}]}` |

- 同时只处理一个请求，正忙时直接返回 `503 busy`，由 Go 后台稍后重试。
- 错误返回 `{error, message}`，和后台的错误格式一致。
- 字级时间戳第一版不返回，只给句级；需要时再加。

### 4.3 运行方式

- 用 NSSM 注册成 Windows 服务 `xiaohe-asr`：开机自动启动，进程退出 10 秒后自动重启，日志写到 `F:\asr\service\logs\`，单个文件 10 MB 滚动。
- 来源限制：服务程序只接受 10.3.19.65 和本机的请求（`ASR_ALLOW`），其他来源返回 403。63 的 Windows 防火墙三个配置文件都是关闭的，防火墙规则虽然加了但不生效，所以限制放在程序里。
- 电源：关闭睡眠和休眠；Windows 更新设置活动时间，避免白天自动重启。
- 安装脚本 `asr/install.ps1` 放在仓库里，从本机用 `sshpass -e ssh Administrator@10.3.19.63` 推上去执行。63 改动少，不走 runner。

## 5. 公网访问：Cloudflare Tunnel

- 用本机 `CLOUDFLARE_API_TOKEN` 通过 API 建一个**远程管理**的 Tunnel `xiaohe-65`，规则在 Cloudflare 侧配置：
  - `personal-repo-api.saulxj.ggff.net` → `http://127.0.0.1:8080`
  - 其他 → `http_status:404`
- DNS：`personal-repo-api` CNAME 到 `<tunnel-id>.cfargotunnel.com`，开代理（橙云）。
- 65 上装 cloudflared（官方 apt 源），以 systemd 服务运行，参数 `--protocol http2`（166 网关的 Clash 对 UDP 不可靠，不用 QUIC）。Tunnel token 只放在 65 的服务配置里。
- 跨域：Web 页面在 `personal-repo.saulxj.ggff.net`，后台在 `personal-repo-api.…`，属于跨域请求。后台只放行 `CORS_ORIGINS` 里的域名；iOS 原生请求不受跨域限制。鉴权用 Bearer token，不用 cookie。

## 6. 部署

### 6.1 65 上的准备（一次性）

1. 建系统用户：`xiaohe`（运行后台，只能写 `/data/db`、`/data/audio`、`/data/backup`）、`runner`（运行 GitHub runner）。
2. 装 Go（官方二进制到 `/usr/local/go`）、cloudflared、`sqlite3`（排查用）。
3. 写 `/etc/xiaohe/env`，装 `xiaohe.service`（`User=xiaohe`、`Restart=always`）。
4. sudoers 只给 `runner` 一条权限：执行 `/opt/xiaohe/bin/release.sh`（发布脚本属 root，runner 不能改）。
5. 注册 runner：届时向你要 runner 注册 token（仓库 Settings → Actions → Runners，1 小时有效），标签 `xiaohe-65`，以 systemd 服务运行。

### 6.2 发布流程（`.github/workflows/deploy-api.yml`）

```yaml
on:
  push:
    branches: [main]
    paths: ['server/**', 'deploy/**', '.github/workflows/deploy-api.yml']
  workflow_dispatch:
jobs:
  test:      # ubuntu-latest：go vet、go test
  deploy:
    needs: test
    runs-on: [self-hosted, xiaohe-65]
    environment: production
    steps: checkout → go build → sudo /opt/xiaohe/bin/release.sh <commit> <二进制路径>
```

`release.sh` 做这些事：

1. 用 `xiaohe backup` 在线备份数据库到 `/data/backup/pre-<commit>.db`；
2. 把程序放到 `/opt/xiaohe/releases/<commit>/`，切换 `current` 软链接；
3. `systemctl restart xiaohe`，程序启动时自动执行新迁移；
4. 30 秒内轮询 `http://127.0.0.1:8080/api/health`，`ok` 且 `db=ok` 才算成功；
5. 失败：软链接切回上一版并重启，工作流标红。数据库不回滚（迁移只增不改，旧程序能用）；确实需要时用第 1 步的备份手动恢复。

现有 `deploy.yml`（静态页面 + Worker）继续运行；切换完成后把 Worker 部分去掉，见第 8 节。

### 6.3 公开仓库上挂 runner 的防护

仓库保持公开，以下几条都要做：
