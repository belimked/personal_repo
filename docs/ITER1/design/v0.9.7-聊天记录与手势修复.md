## 4. 手势修复（逐件过右滑、隐私页左滑）
共同原因：外层 ScrollView 抢走手势后 PanResponder 被终止，且终止时没有归位。统一改法：
- `onMoveShouldSetPanResponderCapture` 和 `onMoveShouldSetPanResponder` 都用横向判断（|dx|>10 且 |dx|>|dy|×1.5）。
- `onPanResponderTerminationRequest: () => false`。
- `onPanResponderGrant` 时让外层 ScrollView `scrollEnabled=false`，释放/终止时恢复（逐件过在 RealReview 内用 state；隐私页通过 FactRows 的 onSwipe(start|end) 回调让 privacy/facts 页控制 ScrollView）。
- `onPanResponderTerminate` 按当前位置吸附（逐件过：归 0；左滑：过半停在 -88，否则归 0）。
- 逐件过：拖动超过 100 或速度 >0.6 即触发“稍后”，过阈值时轻震一次；卡片后面的“暂存，稍后再提醒”底色随距离显现。
- 隐私页左滑：同一时间只开一行（打开新行时关闭旧行）；露出红色“删掉”（宽 88，高度等于行高，文字白色居中）；点“删掉”直接删除（不再二次确认），点行内其他地方收回；行内“不对”仍二次确认。分隔线不随行移动（放在外层 wrap 上）。

## 5. 后台
- `GET /api/messages` 增加 `q`：`content LIKE %q%`（转义 % _ \\），其余分页规则不变。返回每条增加 `item_id`、`item_kind`（转成的事项，没有为 null）。
- 迁移 0007：`ALTER TABLE messages ADD COLUMN item_id TEXT`。
- `POST /api/messages/convert`，请求 `{"ids":["..."],"kind":"todo|watch|idea","scene":"work|life"}`：
  - ids 1～50 条，必须都属于本人 home 线程，否则 400。
  - 按时间顺序拼成对话（“我：… / 小禾：…”），用 XIAOHE_MODEL_JOB 生成 JSON `{"title":"≤20字","note":"≤60字","due":"YYYY-MM-DD|null","owner":"人名|null"}`（取花括号内容再解析）；失败时 title=第一条用户消息截 20 字，note 空。
  - 新建事项：kind 按请求；data = {title, note, scene, due?, owner?, source:{type:"chat", message_ids}}，todo 加 done:false。
  - 更新这些消息的 item_id。写 audit。返回 `{"item":{...}}`。
- 测试：q 搜索与转义、convert 成功（假上游）、上游失败兜底、别人的消息 400。
