## 1. 主 LLM

### 1.1 DeepSeek Flash 规格

来源：https://api-docs.deepseek.com/quick_start/pricing/ 、https://api-docs.deepseek.com/guides/vision/ 、https://api-docs.deepseek.com/guides/json_mode

| 项目 | 内容 | 核实 |
|---|---|---|
| 模型名 | `deepseek-flash`（当前指向 DeepSeek-V4.1-Flash；旧名 `deepseek-v4-flash-vision-exp` 已退役并路由到新模型） | ✅ |
| 上下文长度 | 1M | ✅ |
| 最大输出 | 384K | ◐ |
| 图片输入 | 支持（"accepts images alongside text … describe pictures, read text from screenshots"） | ✅ |
| 每张图片 token 上限 | 1024，不适合密集小字 OCR | ◐ |
| 音频输入 | 不支持 | ◐（文档无音频类型） |
| PDF/文件输入 | 不支持 | ◐ |
| 结构化输出 | `json_object` 模式官方提示"可能偶尔返回空内容"；Responses API 支持 `json_schema`；strict 工具调用为 Beta | ◐ |
| 价格（USD / 百万 token） | 输入（未命中缓存）0.15～0.3，输出 0.6～1.2（闲时/峰时） | ◐ |

### 1.2 是否够用

| 用途 | 结论 |
|---|---|
| 意图识别 + 字段提取（新增/更新/完成/归档/查询） | 够用，需改用 `json_schema` 并在服务端校验、重试 |
| 相对时间解析（"下周三"） | 够用。提示词中注入当前时间、时区、星期，服务端再校验 |
| 1～3 小时会议总结、提取行动项 | 够用。3 小时转写约 6～18 万 token，1M 上下文足够；超长文本建议分块 |
| 判断是否会议、文件归类 | 够用 |
| 照片描述（无文字照片用于检索） | 够用 |
| OCR（扫描件、PDF） | **不够**，需单独的 OCR 模型 |
| 音频转写 | **不能**，由 ASR 负责 |

**最低要求**：中文能力强；上下文约 256K 以上；结构化输出可靠；支持图片输入。

### 1.3 推荐替代（不考虑价格）：Kimi K3.1 Pro

来源：https://platform.kimi.com/docs/models.md

- ✅ Kimi 当前旗舰模型，"原生支持视觉理解，100 万 token 上下文窗口"，中国大陆可直接调用
- ◐ 支持 `response_format` 的 `json_schema` + `strict`（https://platform.kimi.com/docs/guide/response_format.md）
- ⚠ 价格页未能解析，未取得价格
- 建议用法：高频简单任务用 DeepSeek Flash，会议总结等复杂任务切到 Kimi；两者都在模型配置页中可切换

### 1.4 其他候选（子代理整理，均为 ◐）

## 2. ASR（语音转文字）

### 2.1 推荐：阿里云百炼 `fun-asr`

来源：https://docs.bailian.console.aliyun.com/zh/model-studio/asr-model.md 、https://help.aliyun.com/zh/model-studio/non-realtime-speech-recognition-user-guide

| 项目 | 内容 | 核实 |
|---|---|---|
| 支持格式 | aac、amr、avi、flac、flv、m4a、mkv、mov、mp3、mp4、mpeg、ogg、opus、wav、webm、wma、wmv（**含视频**） | ✅ |
| 上限 | 单文件 ≤2GB、≤12 小时 | ◐ |
| 提交方式 | 异步：提交公网 URL → 轮询任务 → 下载结果（结果链接 24 小时有效） | ◐ |
| 说话人分离 | 支持；**建议音频 ≤2 小时，且仅支持单声道** | ◐ |
| 语言 | 普通话 + 七大方言 + 30 个语种 | ◐ |
| 价格 | 0.00022 元/秒，约 0.79 元/小时 | ◐ |

**推荐原因**：能直接接收视频，V1 不用提取音轨；时长和大小上限远超 100MB 单文件限制；中文能力强、价格低；而且我们亲自核实了它的格式表。

**风险**：说话人分离只支持单声道。手机录音一般没问题；电脑录屏的视频会议多为立体声，可能无法区分说话人，需要在原型/测试阶段用真实文件验证。

### 2.2 备选：腾讯云录音文件识别·大模型 2.0（`16k_zh_en_2.0`）

来源：https://cloud.tencent.com/document/product/1093/37823 （子代理通过网页存档读取；主代理抽查时被限流，**未核实**）

- ◐ 格式含 mp4、flv 等视频容器；URL 方式 ≤5 小时、≤1GB
- ◐ 说话人分离可自动区分，最多 20 人（同样要求单声道）
- ◐ 0.8 元/小时，每月 10 小时免费

### 2.3 其他（不推荐作为主选）

| 服务 | 不推荐原因 |
|---|---|
| 火山引擎豆包录音文件识别 2.0 | 不接收视频，只支持 raw/wav/mp3/ogg，需先提取音轨 |
| 讯飞语音转写 | 不接收视频；价格未公开 |
| OpenAI `gpt-transcribe` | 单文件 25MB；不支持 URL 提交；现役模型无说话人分离 |
| Deepgram / AssemblyAI | 中文准确率弱于国内服务；需数据出境 |
| Gemini 3.5 Transcribe | 开启说话人分离时限 30 分钟；大陆不能直连 |

### 2.4 LLM 能否代替 ASR

不建议。DeepSeek 不支持音频；Qwen-Omni 能输入音频，但没有稳定的说话人分离和时间戳。正确分工是：**ASR 转文字 → LLM 总结和提取待办**。

## 3. 视频提取音轨

| 方案 | 结论 | 说明 |
|---|---|---|
| **ASR 直接接收视频（推荐）** | 采用 | 阿里云 `fun-asr` 格式表含 mp4/mov；不会产生中间音频文件 |
| Cloudflare Containers 运行 ffmpeg | 以后需要时再用 | ◐ 官方示例即用 ffmpeg；Workers 付费套餐内含免费额度；冷启动 1～3 秒；估算约 0.001 USD/个文件 |
| Cloudflare Media Transformations（`mode=audio`） | 不推荐 | ◐ 输入 ≤100MB、≤10 分钟，单次输出 ≤60 秒，需切片 |
| 国内云媒体处理（阿里/腾讯 MPS） | 不推荐 | ◐ 输出必须落到该厂商的对象存储 |
| Worker 内运行 ffmpeg.wasm | 不可行 | ◐ Worker 内存仅 128MB |
| 浏览器端提取（ffmpeg.wasm / WebCodecs + Mediabunny） | 不作为主路径 | 移动端内存风险，以后手机 App 也不适用 |
| LLM 提取音轨 | 不可行 | LLM 只输出文字 |

**由此确定的设计**：视频文件不产生中间音频文件；产生一个**转写文本**，作为派生文件永久保存，不计入用户配额。

## 4. 文件上传

- **推荐：浏览器向后端申请预签名地址，直接上传到 R2。**
  - 存储费用与经后端中转完全相同；
  - 不受 Worker 128MB 内存和 100MB 请求体的技术限制；
  - "单文件 ≤100MB（可配置）、批次 ≤300 个/300MB、用户配额 500MB"由系统自身在前端和后端双重校验。
- 每次最多同时上传 3 个文件；单个文件失败可单独重试；V1 不做跨会话断点续传。
- 上传前在浏览器计算 SHA-256，同一用户已有相同文件时提示"直接关联"。
- **不做跨用户去重**：避免泄露"别人是否有这个文件"，也便于删除和合规。

## 5. 已确认的其他决定（来自需求沟通）

- 登录名为邮箱或手机号（必须有邮箱）；密码 8～16 位；只存哈希
- 登录失败锁定：功能做好，V1 默认关闭，管理员可配置
- 忘记密码：邮件重置链接；管理员也可直接设置一般用户密码
- 一般用户默认时区 UTC+8
- 意图识别默认用主 LLM，配置页预留可选的"意图识别模型"
- 完成、归档待办也走文字输入框，执行前需用户确认
- 会议音频：会议本身保存为一条"已完成"待办；行动项写进备注，每条可"转为我的待办"
- 待办不删除，只归档；附件占用配额；用户删除为"先禁用、延期清除"，日志永久保留
