# ITER1 原型 v4 设计
版本：v1

## 1. 目标与范围
### 1.1 要做什么
按评审记录第 10 项“助手页对话化”（`docs/ITER1/review/原型评审变更记录.md` 第 10 节，下称“评审 10.x”，x 为该节编号 1–12）出原型 v4：从 v3 复制到 `public/ITER1/v4/`，v3 冻结。让第一次使用的人一打开就知道可以对话、对话能做什么。
### 1.2 不做什么
- 不接真实大模型、不接后端：识别、问候改写、会议整理、代写初稿都用规则或模板模拟（沿用 v3 的做法）。
- 不改 v1–v3 的任何文件（只在 README、原型首页、评审记录里登记 v4）。
- 不做手机 App；手机布局只做窄屏适配（宽度 ≤ 640px）。
- 发布：全部步骤完成、`node --test tests/` 全部通过后，推送到 GitHub main 分支（自动部署到 https://daily-assistant-proto.accrepo.com/ITER1/v4/），用户已同意（2026-10-27）。

## 2. 使用者与场景
- 新用户第一次登录：进入助手页，助手先问候并带出今天的事，输入框上方有可点的说法，点一下就能体验。
- 老用户：每天第一次打开看到完整问候；之后打开只看变化；随时点“最近安排”查看近几天的事。
- 习惯点菜单的用户：在知识库、待办页看到“问助手”入口，被引导回对话。
- 评审人：对比 v3 与 v4，确认评审第 10 项的 12 点都已体现。

## 3. 功能
### 3.1 v4 目录与测试基础
- 说明：复制 v3 为 v4；演示数据单独保存（localStorage 键 `pa_ITER1_v4`，sessionStorage 前缀 `pa4_`）；页面上的版本字样改为“原型 v4”。建立 jsdom 测试工具（放在 `tests/`，有自己的 package.json，不影响部署）。
- 完成标准：冒烟测试用 jsdom 逐个加载 v4 的全部 HTML 页面（已登录状态），无脚本错误，页面含“原型 v4”字样；v1–v3 文件与提交前一致（`git diff --quiet HEAD~ -- public/ITER1/v1 public/ITER1/v2 public/ITER1/v3`）。

### 3.2 菜单：图标栏与取消“待确认”（评审 10.3、10.7）
- 说明：左侧菜单默认收成图标栏，悬停显示名称（title 或浮层），底部 » 展开 / « 收起，选择记在 localStorage；窄屏不显示左侧菜单（改为顶部简易导航或底部图标条）。菜单去掉“待确认”；`inbox.html` 改为跳转到助手页（同 v3 的 `reminders.html`）。助手菜单显示今天未完成件数（有逾期时红色）。
- 完成标准：jsdom 测试——默认 body/侧栏带收起状态类；点 » 后状态切换且写入 localStorage，重新加载后保持；菜单中没有“待确认”链接；`inbox.html` 含跳转到 `home.html`。

### 3.3 对话式助手页主体（评审 10.1）
- 说明：`home.html` 整页改为聊天：页头头像 + 名字（默认“小禾”，个人设置可改名）+“你的私人助手 · 帮你记事、找文件”。助手先开口：按时段问候并附今天待办卡片（可打勾完成）；有逾期时单独一条消息，附 `改到今天` `改到明天` `已经交了`。回复前显示约 0.5 秒“正在输入”。用户的话为右侧气泡，助手回复为左侧气泡，操作结果为卡片，带 `撤销` `修改`。v3 助手页已有的能力全部保留，改为在对话中进行：记事（含时间识别与归类、追问）、文字 + 附件创建、只传文件、查文件、按意思查待办、单条 / 批量完成（确认卡片）、批量推迟、删除、追加想法。视觉朴素，不用渐变、发光。参考样例 `public/ITER1/samples/chat-home.html`。
- 完成标准：jsdom 测试——打开页面后出现问候消息和今天待办卡片；有逾期数据时出现带三个按钮的逾期消息，点“改到今天”后该待办日期变为今天；输入“周五3点体检”并发送，先出现“正在输入”，之后出现用户气泡和带“撤销”的结果卡片，状态里新增一条待办；点“撤销”后该待办被移除；输入“今天的事儿，我都完成了”出现批量完成确认卡片。

### 3.4 建议说法、随用随提示、“最近安排”（评审 10.4、10.5、10.6）
- 说明：输入框上方一行可横向滑动的建议说法（覆盖记事、查文件、按意思查待办、批量推迟、批量完成），点一下直接发送；输入框提示“跟我说就行，比如：周五3点体检”；语音按钮在输入框内。每种能力第一次用完后在回复底部附一行 💡 提示，同一种只出现一次（记在 localStorage）。“📅 最近安排 N”按钮固定在建议说法行最左侧、不随滑动；有逾期时红色角标；点击弹出面板（窄屏为底部弹出）：已逾期、今天、明天、后天、期限快到的待安排事项，可打勾；底部 `去待办页 ›`、待安排件数、邮件提醒设置入口；点 ×、面板外、再点按钮均关闭；面板内容不进聊天记录。去掉 v3 的“近 3 天”区域。
- 完成标准：jsdom 测试——点击一条建议说法后对话中出现该用户气泡；第一次记事后回复含 💡 提示，第二次记事不再出现同一提示；按钮文字中的 N 等于今天未完成件数；有逾期时角标数字等于逾期件数；打开面板后聊天消息条数不变；三种关闭方式都能关闭面板；页面不再有 v3 的“近 3 天”区域。

### 3.5 会议消息、对话记录、问候规则（评审 10.2、10.8、10.9、10.10）
- 说明：有待处理会议（`state.inbox` 中未处理的会议）时，助手主动发消息说明整理出几条待办、几条分给你，按钮 `一起过一下` `晚点再说`；逐条勾选后加入待办，每条可“听原话”（显示原文片段和时间点）；“晚点再说”后本次会话稍后（原型中约 30 秒或下次打开）再提醒一次。对话记录按天保存在 localStorage，默认只显示今天，往上滚或点“查看更早的对话”加载更早的，超过 30 天的自动清理。问候：每天第一次打开完整问候（今天的事、逾期、待处理会议）；当天再打开只说有变化的内容，没有变化不发消息。问候文本由程序按“模板 + 数据”组成，再经“模拟改写”加节日 / 天气开场（节日表由程序提供，含农历节日的演示数据）；数字和时间以程序数据为准；每人每天只生成一次完整问候并缓存。
- 完成标准：jsdom 测试——有未处理会议时出现会议消息；勾选 2 条并确认后待办数增加 2，会议标记为已处理；同一天第二次加载页面不再出现完整问候；伪造 31 天前的记录后加载页面，该记录被清理；把“今天”设成演示节日表中的某天时问候含该节日名。

### 3.6 代写文档（评审 10.12）
- 说明：新增写作类待办（标题含 周报 / 方案 / 介绍 / 总结 / 报告）或会议整理出写作类事项时，助手提示一次，带 `好，开始` `不用了`。开始后：在知识库里找类似文档作参考（模拟按意思匹配）；周报自动整理本周已完成待办和想法记录，再问是否补充；生成文字初稿显示在对话中（模板拼装，只用已有数据，缺素材时写明缺什么）；可复制、可“导出 Word”（下载 .doc，HTML 格式即可）；同时存入知识库并挂到对应待办。每件事只提示一次；同类连续拒绝 3 次后不再主动提示该类。
- 完成标准：jsdom 测试——输入“下周三交周报”后出现代写提示；点“好，开始”最终出现初稿卡片，知识库新增一份文件且该待办附件包含它；对同类事项连续点 3 次“不用了”后，第 4 次新建不再提示；初稿中不出现素材里没有的数字（测试检查初稿中的数字都来自演示数据）。

### 3.7 各页“问助手”入口（评审 10.11）
- 说明：知识库搜索框提示改为“用一句话描述你要找的内容”，旁边注明“按意思找”；待办页顶部一行“跟助手说：把这周所有会议推迟一天”，带输入框。在这些入口输入并回车后跳到 `home.html?ask=<文字>`，助手页自动把这句话作为用户消息发送并处理。个人设置增加“助手名字”。
- 完成标准：jsdom 测试——知识库页、待办页存在上述入口；在入口提交后页面跳转地址为 `home.html?ask=...`（测试拦截跳转并检查地址）；以 `?ask=找合同` 加载助手页时，对话中出现“找合同”用户气泡和查询结果；个人设置改名后助手页页头显示新名字。

### 3.8 版本登记与文档
- 说明：README 版本索引新增 v4（评审中），v3 改为冻结；原型首页 `public/index.html` 加 v4 入口；评审记录第 10 项状态改为“已改原型（v4）”，头部“改动落地版本”补充 v4 说明，末尾新增“v4 原型实现说明”（模拟方式与差异）；打本地 git 标签 `ITER1-proto-v4`（不 push）。

## 4. 技术方案
- 纯静态多页 HTML + 原生 JS + CSS，与 v3 相同，部署到 Cloudflare 静态资源（`wrangler.json`），无构建步骤。
- 公共逻辑在 `public/ITER1/v4/assets/app.js`、样式在 `app.css`、演示数据在 `data.js`；助手页逻辑可放在 `home.html` 内或新文件 `assets/chat.js`。
- 测试：`tests/` 目录自带 `package.json`（devDependencies：jsdom），测试用 Node 自带 `node:test`。首次运行 `npm --prefix tests install`。运行测试：`node --test tests/`；冒烟：`node --test tests/smoke.test.mjs`。根目录不放 package.json，避免影响部署流程。
- 测试中需要固定“今天”和登录状态：通过 jsdom 在页面脚本运行前注入 localStorage（session）和可选的日期覆盖（在 app.js 中支持 `window.PA_TODAY` 覆盖今天，仅测试使用）。
- “正在输入”等延时在测试中可用较短的时间或 fake timer 处理，测试总时长控制在 2 分钟内。

## 5. 数据
沿用 v3 的 localStorage 状态结构（键改为 `pa_ITER1_v4`），新增：
- `prefs.assistantName`：助手名字，默认“小禾”。
- `prefs.navExpanded`：菜单是否展开。
- `chat`：`{ "<YYYY-MM-DD>": [消息...] }`，保留 30 天；`greetedOn`、`greetSnapshot`（判断当天是否完整问候过及之后的变化）。
- `tipsShown`：已出现过的提示种类；`writeOffer`：`{ 已提示的待办 id 列表, 各类连续拒绝次数 }`。
- `inbox` 中会议增加 `remindLater` 标记。
