# ITER1 原型 v5 设计
版本：v1

## 1. 目标与范围
### 1.1 要做什么
按 v4 评审的第 11、12、13 项（`docs/ITER1/review/原型评审变更记录.md`）出原型 v5：从 v4 复制到 `public/ITER1/v5/`，v4 冻结。重点是第 13 项：待办必须有日期，没有日期的改为与待办平级的“想做的事”，单独一页，可以生成关联待办；新增“灵光一现”标签。同时做第 11 项（菜单收起按钮）和第 12 项（待办页左侧标签树）。
### 1.2 不做什么
- 不接真实大模型、不接后端：时间识别、自动打标签（含“灵光一现”判断）都用规则模拟，沿用 v4 的做法。
- 不改 v1–v4 的任何文件（只在 README、原型首页、评审记录里登记 v5）。样例目录 `public/ITER1/samples/` 不改。
- 第 12 项“待定”中：助手页按标签查询、知识库侧栏改多选、“最近安排”面板加标签筛选，本版都不做；标签树件数跟随当前页签（列表）或当前显示范围（日历）；窄屏时标签树收成顶部“🏷️ 标签 ▼”按钮。
- 不做手机 App；窄屏（≤ 640px）只做适配。
- 发布：开发全部完成、本机测试和 GitHub 上的浏览器测试都通过后，推送 main 自动部署到 https://daily-assistant-proto.accrepo.com/ITER1/v5/ ，用户已同意（2026-10-29）。

## 2. 使用者与场景
- 用户对助手说“想研究一下保险”：记成一件想做的事，结果卡片问要不要定个时间；点“这周末”就生成一条关联待办。
- 用户说“下个月要买车险”：直接成为待办，截止日是下个月最后一天，显示“11/30 前”。
- 用户偶尔打开 💡“想做的事”页翻一翻，按标签筛选，点“排个时间”生成待办，或把一件事标成“做成了 / 放下了”。
- 用户在待办页只看到有日期的待办，左侧标签树可以多选、排除。
- 评审人对比 v4 与 v5，确认第 11–13 项都已体现。

## 3. 功能
### 3.1 v5 目录、测试工具、菜单按钮（第 11 项）
- 说明：复制 v4 为 v5；localStorage 键 `pa_ITER1_v5`，sessionStorage 前缀 `pa5_`，页面版本字样改为“原型 v5”。`tests/helpers.mjs` 支持按版本加载页面（默认仍是 v4，旧测试不受影响），新增 v5 冒烟测试。菜单底部收起/展开按钮改为 SVG 图标（侧栏框 + 箭头，约 18–20px，展开 / 收起两种方向），与菜单项同样大小的点击区域、同色、悬停浅底，title 为“展开菜单”/“收起菜单”；展开时显示图标 + “收起菜单”。
- 完成标准：v5 冒烟测试逐个加载 v5 全部页面无脚本错误、含“原型 v5”、不含“原型 v4”；`#nav-toggle` 内含 `svg`，不含字符“»”“«”，收起时 title 为“展开菜单”、展开时为“收起菜单”；v1–v4 文件未改动；v4 旧测试全部通过。

### 3.2 数据模型：想做的事、待办必须有日期（第 13 项 1–3）
- 说明：
  - 新增 `state.ideas`（字段见 §5）。待办新增可选 `ideaId`（来源）。待办必须有 `date`：带期限的待办 `date` 取期限最后一天，保留 `deadline`（显示“11/30 前”，最后 7 天进“期限快到了”，过了算逾期）。
  - 演示数据迁移：v4 中没有日期也没有期限的待办改为想做的事（“整理家里的旧衣服”“研究新能源车的购车补贴”，保留星标、想法记录、附件）；有期限的（买车险、更新简历、预约年底体检）改为带截止日的待办。另加演示：“研究一下保险”（关联已有待办“联系平安的客户经理”）、“想学游泳”、“带孩子去趟云南”、灵光一现两件（“周报可以加个图表”“做个记家里开销的小程序”），其中一件超过 90 天没动静（供回顾演示）。
  - 公共函数（放 app.js，导出到 `PA`）：`ideaById`、`linkedTodos(idea)`、`ideaProgress(idea)`（已排 N 条 · 完成 M）、`todoFromIdea(idea, {date,time,title?})`（生成关联待办，继承标签，返回待办）、`todoToIdea(todo)`（待办转为想做的事并删除待办）、`isSpark(idea)`（是否带“灵光一现”）。
  - 时间归类（`parseWhen` 的使用方）：具体日期 → 待办；时间段 → 待办，`date` = 期限最后一天；无时间 → 想做的事。
  - 自动打标签：预设标签库新增“灵光一现”（只用于想做的事）。原型用规则模拟：标题或内容含“可以加 / 可以试试 / 要是能 / 做个 / 搞个 / 突然想到 / 点子 / 灵感 / 也许可以”等说法时打上；用户去掉后记入该想做的事的 `tagsRemoved`，不再加回。
- 完成标准：jsdom 测试——v5 演示数据中所有未删除的待办都有 `date`；`state.ideas` 含上述演示条目且“研究新能源车的购车补贴”保留星标和 2 条想法记录；`todoFromIdea` 生成的待办带 `ideaId`、标签与想做的事一致；`ideaProgress` 返回正确的条数；`todoToIdea` 后待办消失、新想做的事标题一致；“周报可以加个图表”带“灵光一现”，“想学游泳”不带。

### 3.3 “想做的事”页面（第 13 项 4）
- 说明：菜单在“待办事项”下面新增 💡“想做的事”（`ideas.html`）。页面只有一列卡片：
  - 顶部一个输入框“记一件想做的事…”，回车即新增（自动打标签）；下面一行标签小块：`全部` `灵光一现` + 本页用到的其他标签，点一下筛选（单选）。
  - 卡片：标题、最新一条想法的开头、⭐、📎 数量、关联待办进度（“已排 2 条 · 完成 1”，没有就不显示）、“N 天前更新”；主按钮只有 `排个时间`，点开日期快捷选项（今天 / 明天 / 这周末 / 下周一 / 选日期），选了生成一条关联待办，并提示“已排到 X，可撤销”。排序：星标 → 最近更新。
  - 默认只显示“进行中”；底部一行“已做成 N · 已放下 N ›”可展开查看。
  - 点卡片标题进详情页 `idea.html?id=`：标题、标签（可改）、备注、想法记录（沿用 v4 的想法记录组件，带附件）、附件、关联待办列表（可打勾、可点进）、状态按钮 `做成了` `放下了`（已结束的显示 `恢复`）、`删除`。
- 完成标准：jsdom 测试——菜单含“想做的事”链接；ideas.html 列出所有进行中的演示条目；点“灵光一现”小块后只剩两件灵光一现；在输入框输入“想学吉他”回车后新增一张卡片；对某件点 `排个时间` → `明天` 后，待办里新增一条 `ideaId` 指向它、日期为明天的待办，卡片进度变为“已排 1 条”；idea.html 详情显示关联待办，点 `放下了` 后状态变为 dropped，回到列表不再显示该条。

### 3.4 待办页减负与标签树（第 13 项 4、第 12 项）
- 说明：
  - 去掉“待安排”页签、列表的“待安排”分组、日历右侧的待安排栏，以及“拖回待安排栏清除日期”。带截止日的待办在列表和日历上显示为“截止 · 买车险”或“11/30 前”。
  - 新建 / 编辑待办必须有日期：日期快捷选项里选“期限”时自动把日期设为期限最后一天；什么都没选时“保存”不可用，旁边提示“还没定日子？放进想做的事 ›”，点了就存为想做的事。编辑时不能清空日期。
  - 待办详情（`todo.html` 和右侧详情）：有 `ideaId` 时显示一行“来自：<想做的事标题> ›”链到 idea.html；去掉星标；增加 `先不做了`（有来源就只删除这条待办，没有来源就转成想做的事），带撤销。
  - 左侧标签树：按第 12 项实现，交互参照样例 `public/ITER1/samples/todo-tags/todos.html`，并补上样例没有的“全选 / 全不选（Excel 筛选式）”：默认全勾（含“未打标签”），取消即排除；全不勾时列表为空并提示“没有勾选任何标签 · 全选”；新出现的标签在“排除”模式下默认勾上、“只看”模式下默认不勾；筛选行文字“标签：除了 工作”/“标签：生活/缴费 + 工作/会议”。列表和日历共用筛选；标签栏可收起；件数跟随当前页签或日历显示范围；窄屏收成顶部按钮。
  - 待办页顶部的“问助手”入口保留。
- 完成标准：jsdom 测试——待办页没有“待安排”字样的页签、分组和侧栏；新建表单不选日期时保存按钮禁用，点“放进想做的事”后 ideas 增加一条；选“本周内”期限保存后待办 `date` 为本周最后一天；有 `ideaId` 的待办详情含“来自：”链接；点 `先不做了` 后无来源的待办转为想做的事；标签树默认全勾，取消“工作”后列表不含任何工作标签的待办、筛选行含“除了 工作”；点全选框变为全不勾后列表为空且有“全选”提示；只勾“生活/缴费”时只显示该类。

### 3.5 助手：记录、排期、查询（第 13 项 2、3、5）
- 说明：
  - 没有时间的说法（如“想研究一下保险”）记成想做的事。结果卡片：“记成想做的事了，要定个时间去做吗？”，带 `今天` `明天` `这周末` `下周` `选日期` 和 `撤销`；点日期生成关联待办，卡片改为“已排到 X”。不理会就保持为想做的事。卡片注明“没排日期，不算待办”。
  - 时间段说法（“下个月要买车险”）直接成为待办，卡片写清截止日：“已加入待办：11月30日（周日）前 · 买车险”。
  - “保险那件事，再记一下：……”可以追加到想做的事（先匹配想做的事，再匹配待办）；“保险那件事，排到周六上午”从想做的事生成关联待办（想做的事保留）。
  - 按意思查询的结果包含想做的事及其想法记录，卡片里标明“想做的事”，带 `排个时间`。
  - “📅 最近安排”面板底部的“待安排 N 件”改为“想做的事 N 件 · 看看 ›”（链到 ideas.html）；面板里“期限快到了”一节列截止日在 7 天内的待办。
  - 首次记成想做的事后附 💡 提示：“没定时间的事我记在‘想做的事’里，不会催你；想做了就说‘XX 那件事排到周六’。”
- 完成标准：jsdom 测试——发送“想研究一下保险理财”后 ideas 增加一条，待办数不变，卡片含“想做的事”和 `明天` 按钮；点 `明天` 后新增一条带 `ideaId` 的明天的待办；发送“下个月要买车险”后新增待办的 `date` 为下月最后一天；发送“新能源车那件事，再记一下：问问以旧换新”后该想做的事的想法记录增加 1 条；发送“保险那件事，排到周六上午”后新增一条关联待办，想做的事仍在；最近安排面板含“想做的事”和链到 ideas.html 的链接。

### 3.6 助手：逾期、做成了、会议、回顾（第 13 项 3、7、8）
- 说明：
  - 逾期消息的按钮增加 `先不做了`（规则同 §3.4 的 `先不做了`）。
  - 某件想做的事的关联待办全部完成后（在助手页打勾完成或打开助手页时检测），助手问一次“『研究一下保险』排的事都做完了，这件事算做成了吗？”，带 `做成了` `还没`；选“还没”后不再为这件事的同一批待办发问。
  - 会议确认：逐条勾选时每条带日期——录音里提到的直接显示（演示数据中有 `due` 的），没提到的显示 `选日期`（点开快捷选项）；点确认时如果勾选的条目里还有没定日期的，提示“有 N 条没定日期，先放进想做的事？”，带 `放进想做的事` `回去选日期`。有日期的变成待办，没日期的变成想做的事（来源注明会议名）。
  - 回顾：每周一第一次打开助手页，问候之后加一条“你有 N 件想做的事，有要排进这周的吗？”，列出前 5 件（不含灵光一现），每件带 `排个时间`；每月 1 日第一次打开，加一条“上个月记了 N 个灵光一现，翻翻看？”，带 `去看看`；同一条消息里顺带问超过 90 天没动静的普通想做的事“还留着吗？”，带 `留着` `放下了`。演示：助手页地址加 `?review=week` 或 `?review=month` 可以随时触发对应回顾（原型首页说明）。
- 完成标准：jsdom 测试——有逾期待办时逾期消息含 `先不做了`，点后该待办不在待办里、ideas 多一条；把某件想做的事的最后一条关联待办在助手页打勾完成后出现“算做成了吗”消息，点 `做成了` 后状态为 done；会议确认时只勾一条无日期条目并确认，出现“先放进想做的事”提示，点后 ideas 增加一条；以 `?review=week` 加载助手页出现每周回顾消息且不含灵光一现条目；以 `?review=month` 加载出现灵光一现回顾和 90 天询问。

## 4. 技术方案
- 纯静态多页 HTML + 原生 JS + CSS，与 v4 相同，部署到 Cloudflare 静态资源（`wrangler.json`），无构建步骤。架构：site-builder 的 `static`。
- 公共逻辑 `public/ITER1/v5/assets/app.js`，样式 `app.css`，演示数据 `data.js`，助手页 `chat.js`。
- 本机测试：`tests/`（自带 package.json，jsdom，`node:test`）。首次 `npm --prefix tests install`。全部测试：`node --test "tests/*.test.mjs"`；冒烟：`node --test tests/v5-smoke.test.mjs`。v5 的测试文件统一以 `tests/v5-` 开头。测试中固定“今天”用 `window.PA_TODAY`。
- 浏览器测试（只在 GitHub 上跑）：根目录新增 `package.json`（devDependencies：`@playwright/test`、`wrangler`；`test` 脚本运行本机 jsdom 测试），`playwright.config.ts`，`.github/workflows/test.yml`，`e2e/*.spec.ts`；服务用 `npx wrangler dev --local --port 4173`。根目录新增 package.json 后 deploy 流程会先 `npm install`，没有 build 脚本，不影响部署。
- 发布：site-builder `publish.sh`；之后 `git push origin ITER1-proto-v5`。

## 5. 数据
沿用 v4 的 localStorage 状态结构（键改为 `pa_ITER1_v5`），变化：
- `ideas`：`[{ id, title, notes, records: [{id, at, text, files}], attachments: [], tags: [], tagsRemoved: [], starred, status: "active"|"done"|"dropped", source: "text"|"manual"|"meeting"|"todo", sourceNote, createdAt, updatedAt, askedDone: [待办 id 列表] }]`。
