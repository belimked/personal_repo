## 过程中的两次失败与处理（均为测试写错，未改网站代码）

1. 运行 https://github.com/alangao2025-dev/daily-assistant-proto/actions/runs/40905713059 ：7 failed / 1 passed。
   - 原因：wrangler 静态资源把 `home.html`、`todos.html` 规整成无扩展名地址（实际 URL `/ITER1/v5/home`），`e2e/helpers.ts` 和 `e2e/auth.spec.ts` 里的 `toHaveURL(/home\.html$/)`、`/todos\.html$/` 断言过严。
   - 处理：改为 `/home(\.html)?$/`、`/todos(\.html)?$/`，断言内容不变（仍校验跳到助手页 / 待办页）。
2. 运行 https://github.com/alangao2025-dev/daily-assistant-proto/actions/runs/40906532443 ：1 failed / 7 passed。
   - 失败用例：TC-07，期望待办**列表**里出现“来自：周报可以加个图表”，实际列表行不显示来源行。
   - 判定：测试写错。设计 §3.4（L47）只要求“待办详情（`todo.html` 和右侧详情）有 `ideaId` 时显示一行‘来自：…’”，`todos.html` 列表行本就不显示来源行。
   - 处理：TC-07 改为在待办列表点该行“详情”进 `todo.html?id=…`，再断言 `[data-from]` 含“来自：”并链到该想做的事；用例覆盖范围不变（筛选 → 排时间生成待办 → 待办带来源）。

未出现“网站 bug”类失败，未放宽或删除任何用例断言。
