# 个人日常助手（原型 v5）测试方案

- 被测对象：daily-assistant-proto 的 v5 原型，纯静态多页 HTML + 原生 JS，入口 `public/ITER1/v5/index.html`（登录页），架构 `static`，部署到 Cloudflare 静态资源。
- 测试范围：登录、侧栏菜单、待办页（无“待安排”、标签树排除）、想做的事页（新增 / 筛选 / 排时间生成待办）、助手页的每周回顾演示。本机再跑已有的 jsdom 用例（`tests/*.test.mjs`）。
- 不测：管理端页面（用户 / 模型 / 系统设置 / 文件类型 / 用量 / 日志）的完整流程；真实邮件、真实模型调用、文件上传解析；线上地址（由 site-builder 的 `publish.sh` 单独检查）。
- 测试环境：浏览器用例只在 GitHub Actions 上跑（快照 + `npx wrangler dev --local --port 4173`，Chromium），不连线上数据；本机只跑 `npm test`（jsdom）和 `npx playwright test --list`，本机不下载浏览器。

## 测试数据

- 浏览器用例全部用演示数据：`assets/data.js` 的种子待办/想做的事，登录账号 lily@demo.com / demo1234（只读演示账号，无真实密码）。
- 每个用例自己造改动数据：TC-04 新增“整理露营装备”，TC-07 给“周报可以加个图表”排时间；只在本用例的浏览器 context 里生效，不依赖其他用例顺序。
- 日期相关用例只断言“有 / 没有”“已排 1 条”“来自：”等结果，不写死具体日期，避免跨天失效。

## 通过标准

- GitHub Actions 上 `npx playwright test` 全部通过，运行结论为 success；
